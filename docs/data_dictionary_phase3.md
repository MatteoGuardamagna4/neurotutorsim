# Phase III data dictionary

Every column of every Phase III output table: type, units, provenance.

Phase III spans brief §7 and the §10.2/§10.3 validation checks. It **ends at
`E_iut`** — the effort term Phase IV multiplies by the predicted cortical response
`Z(u,c,p)`. Nothing here is a neural quantity, nothing here reads a TRIBE
artefact, and no plasticity is computed.

Conventions used throughout:

* Every learner is a **simulated** learner drawn from the §7.1–7.2 generative
  model. No participant was measured. Differences between conditions are scenario
  contrasts, not causal effects.
* `learner_id` — `0 … n_learners - 1`, assigned at initialisation. Stable across
  conditions within a run: the same learners are run through every condition, so
  `learner_id` joins the arms.
* `condition` ∈ `traditional`, `ai_scaffolding`, `ai_substitution`, and optionally
  `static_ai`.
* `episode` / `time` — 0-based episode index. Both name the same quantity; the two
  spellings come from the §4.2 schemas.
* Every state component (`K`, `M`, `R`, `C`, `D`) lies in [0, 1] by eq. (15).
* "logit scale" — the additive scale of eq. (17)–(18). `theta` and `b_u` live
  there; nothing else does.

### Two additions to the §4.2 schemas

Recorded here and in `docs/phase3_assumptions.md` §17, because the schemas as
declared do not identify a row:

* `responses.csv` gains **`stage`** and **`episode_id`** — §3.1 scores three
  responses per learner per episode, so `learner_id + episode + condition` is not
  a key.
* `learner_state.parquet` gains **`condition`** — three conditions share a
  `(learner_id, time)` key.

Nothing was removed or renamed.

## 1. Units table (input) — passed by explicit `--units` path

Read by `src/learners/curriculum.py`. There is no corpus discovery: a
corpus-independent engine must be told which corpus it is simulating over.

### Required columns

| column | type | units | provenance |
|---|---|---|---|
| `unit_id` | str | — | source table; opaque to the engine, never parsed |
| `domain` | str | — | source table |
| `concept` | str | — | source table |
| `difficulty` | int | 1–5 | §5.1 item 5; non-integer or out-of-range **raises** |

### Optional columns, carried through when present

| column | type | units | provenance |
|---|---|---|---|
| `provenance` | str | — | source table; defaults to `unspecified`, which is treated as **real** |
| `coverage` | float | [0, 1] | Phase I §5.4 semantic coverage; defaults with a warning |
| `correctness` | float | [0, 1] | Phase I §5.4 validator outcome; defaults with a warning |
| `prerequisites` | str | — | source table |
| `reference_answer` | str | — | source table |
| `transfer_answer` | str | — | source table |
| `misconception_answer` | str | — | source table |
| `misconception_description` | str | — | source table |

### Added by the loader

| column | type | units | provenance |
|---|---|---|---|
| `b_u` | float | logits | `b_intercept + b_slope * (difficulty - difficulty_center)` — an ASSUMPTION, see `phase3_assumptions.md` §1 |

**Decision gate 16.** `load_curriculum` raises a `ValueError` naming gate 16 when a
table has fewer than `curriculum.min_units` rows and is not stamped
`synthetic_placeholder` on **every** row. There is no override flag.

## 2. Placeholder corpus — `data/synthetic/units_placeholder.csv`

Generated by `scripts/make_placeholder_units.py`. Committed, a few KB.

**Every unit is fictitious.** No output derived from this table is a project
result; it exists so the engine can be exercised while gate 16 is open. Adds one
column to the units schema above:

| column | type | units | provenance |
|---|---|---|---|
| `band` | str | — | `introductory` \| `intermediate` \| `advanced`, one third each (§5.1 item 2). Dropped by `load_curriculum` — a diagnostic for the generating script, not an engine input. |

`unit_id` has the form `SYNTH_<domain>_<nnn>`; `reference_answer` and
`misconception_answer` are tokens (`SYNTH_ANSWER_017`), never numbers, so a leaked
value cannot be mistaken for a validated result.

## 3. Responses — `data/processed/responses.csv`

One row per **scored response**. Streamed in chunks; at 5,000 learners × 120
episodes × 3 conditions this is ~5.4M rows.

A row exists only for a response that happened: a learner who never attempted has
no `first` row, and one who was right first time has no `supported` row. Padding
with placeholder rows would put responses that were never scored into every
accuracy denominator.

| column | type | units | provenance |
|---|---|---|---|
| `learner_id` | int64 | — | population index |
| `episode` | int64 | episodes | 0-based episode index |
| `episode_id` | str | — | **added.** `ep<NNNN>\|<unit_id>`; constant across conditions for the same unit at the same index, so a within-unit contrast joins on it |
| `condition` | str | — | the §3.2 instructional condition |
| `stage` | str | — | **added.** `first` (unaided), `supported`, `transfer` (unaided) |
| `prompt` | str | — | structured descriptor `unit\|condition\|stage\|d=<difficulty>\|h=<support>`. **Not free text** — the logistic engine has no prompt |
| `response` | str | — | `correct`; `misconception` where the unit documents one, else `incorrect` |
| `answer` | str | — | the unit's `reference_answer` or `misconception_answer`; `unspecified` where the units table has neither. **No answer is invented** |
| `confidence` | float | [0, 1] | `clip(p_correct + bias_i + eps, 0, 1)` — ASSUMPTION, see `phase3_assumptions.md` §4 |
| `correctness` | int64 | {0, 1} | the drawn outcome for this response |
| `latency_proxy` | float | seconds | `speed_i * (base + per_hint*depth + attempt*attempted)` — a bookkeeping proxy, **not a reaction-time prediction** |
| `token_count` | int64 | fields | **descriptor fields, not LLM tokens.** The column exists so the schema is identical whichever engine produced the row |

### What `correctness` means at each stage

* `first` — the learner's own unaided attempt. The only response in the episode
  not confounded by support.
* `supported` — the response under support level `h`. **1 whenever the answer was
  revealed**, so this is not a measure of competence.
* `transfer` — the unaided transfer question, at `b_u + transfer_b_delta`.

## 4. Learner state — `data/processed/learner_state.parquet`

One row per learner × episode × condition. Written as parquet row groups, one per
chunk. Gitignored: a build product of a seeded run, reproducible from the config
hash and the master seed.

| column | type | units | provenance |
|---|---|---|---|
| `condition` | str | — | **added.** Three conditions share a `(learner_id, time)` key |
| `learner_id` | int64 | — | population index |
| `time` | int64 | episodes | 0-based episode index |
| `K` | float | [0, 1] | knowledge, eq. (21), **after** this episode's update |
| `M` | float | [0, 1] | memory strength, eq. (22) |
| `R` | float | [0, 1] | independent reasoning, eq. (23) |
| `C` | float | [0, 1] | calibration, `1 - running Brier` (§7.6 deviation, eq. 24) |
| `D` | float | [0, 1] | dependence, eq. (25) |
| `effort` | float | (0, 1) | `E_iut`, eq. (19). **The Phase III → IV handoff quantity** |
| `support` | float | [0, 1] | realised support level `h`, after the persistence modifier |
| `correctness` | int64 | {0, 1} | the episode's **unaided** first response |

## 5. Checkpoints — `outputs/tables/phase3_checkpoints.csv`

One row per learner × checkpoint × condition. Every probe is scored with **all
support removed**, except `supported_accuracy_trained`, which exists so eq. (26)
has something to subtract from. A checkpoint never mutates learner state.

| column | type | units | provenance |
|---|---|---|---|
| `learner_id` | int64 | — | population index |
| `condition` | str | — | the arm this checkpoint belongs to |
| `checkpoint_episode` | int64 | episodes | the episode the checkpoint follows |
| `stratum_index` | int64 | — | 0/1/2 = low/medium/high prior knowledge |
| `unaided_accuracy_trained` | float | [0, 1] | trained items, `h = 0` |
| `supported_accuracy_trained` | float | [0, 1] | same items at `h = probe_h` |
| `support_gap` | float | [-1, 1] | eq. (26): supported − unaided |
| `near_transfer_accuracy` | float | [0, 1] | `b_u + near_b_delta`, `h = 0` |
| `far_transfer_accuracy` | float | [0, 1] | `b_u + far_b_delta`, `h = 0` |
| `retention_accuracy` | float | [0, 1] | trained items after a decay-only projection |
| `retention_interval_episodes` | int64 | episodes | the configured no-practice interval |
| `brier_score` | float | [0, 1] | eq. (27) over this checkpoint's **unaided** forecasts. **Lower is better** |
| `expected_calibration_error` | float | [0, 1] | 10-bin ECE, **per learner**. Coarse by construction — see `phase3_assumptions.md` §12 |
| `dependence` | float | [0, 1] | P(requesting assistance before an independent attempt), averaged over the trained items. **Recorded, never granted** — the checkpoint removes support |
| `n_trained_items` | int64 | items | probe composition |
| `n_near_items` | int64 | items | probe composition |
| `n_far_items` | int64 | items | probe composition |
| `K`, `M`, `R`, `C`, `D` | float | [0, 1] | state at the checkpoint, unmodified |

**Reading `support_gap`.** A positive gap is expected in *every* condition —
eq. (18) adds `omega * h` to the logit, so support raises accuracy by
construction. What is informative is a large gap paired with a low
`unaided_accuracy_trained`: competence that exists only while the system is
present. It is not a measure of learning.

## 6. Validation report — `outputs/tables/phase3_validation_report.md`

**Generated by `src.learners.simulate.render_validation_report`. Never
hand-edited.** Carries the run's identity, warnings, clip counts, per-condition
episode means, checkpoint means, and the §10.6 separation verdict.

A run over the placeholder corpus opens with a banner saying so. The §10.6 verdict
is written whether or not the conditions separated: an absent difference is a
falsification signal about the model, and this is where it is recorded rather than
passed over.

## 7. Run log — `outputs/logs/phase3_run_<timestamp>.json`

Gitignored. One per run.

| key | type | provenance |
|---|---|---|
| `config_hash` | str (64 hex) | `sha256` of the canonical JSON of the resolved config |
| `master_seed` | int | `seeds.master` |
| `git_commit` | str \| null | `git rev-parse HEAD`; null outside a checkout |
| `packages` | object | installed versions of the Track B stack |
| `python`, `platform` | str | interpreter and OS |
| `n_learners`, `n_episodes`, `conditions`, `n_units` | int / list | run scope |
| `placeholder_corpus` | bool | true when every unit is `synthetic_placeholder` |
| `row_counts` | object | responses, learner_state, checkpoints |
| `clip_counts` | object | per state component: `clipped`, `total`, `share` |
| `warnings` | list of str | every defaulted column, named |
| `wall_time_s` | float | wall clock for the run |
| `separation` | list of object | the §10.6 verdicts |
| `outputs` | object | absolute paths of the four tables |
| `recorded_utc` | str | ISO 8601, write time |

**`clip_counts` is a diagnostic, not bookkeeping.** Heavy clipping means the
parameters are wrong — a population pinned at `D = 1` is not a finding. A first
parameterisation of this build clipped `D` on 47% of updates, and this is the field
that made it visible. See `phase3_assumptions.md` finding F1 for why eq. (23) and
eq. (25) make some clipping structural.

## 8. Minitaur feasibility report — `reports/minitaur_feasibility.md`

Generated by `scripts/benchmark_minitaur.py` on a Colab GPU. Currently a committed
**NOT-YET-RUN placeholder** holding the preregistered method and no numbers,
because a GO/NO-GO decision would otherwise rest on invented figures.

When run, it records the pinned revision, the environment, peak VRAM, seconds per
scored episode, mean prompt token count, and the extrapolation to the §10.2 target
with its arithmetic shown.

---

## What Phase III does **not** produce

No neural or cortical quantity. No `Z(u,c,p)`. No plasticity state, no `N`, no
scenario contrast, no phase diagram. Those are Phase IV (§8–§9) and are out of
scope by design: TRIBE and the learner engine are parallel tracks that meet only
inside the plasticity equation `N ← (1-δ)N + η · E · Z`, where this phase supplies
`E` and Phase II supplies `Z`.
